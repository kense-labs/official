目标不是配齐全部集成，而是在 15 分钟内完成一次可复盘的工作。下面的顺序刻意保守：先边界，再执行，最后才考虑发布。

<h2 id="step-1">1. 选定一个真实任务</h2>

- 任务必须有输入与产出（一份 brief、一个仓库、一组表格）。
- 任务应能在本机完成，不依赖尚未批准的生产密钥。
- 成功标准写清楚：例如“产出可审阅的纪要，而不是一段闲聊”。

<h2 id="step-2">2. 在 Work 里圈定权限</h2>

只挂载需要的目录与工具。最小权限能让失败可诊断：Agent 做不到某件事时，应是授权不足，而不是隐式全盘访问。

<h2 id="step-3">3. 跑通并留下证据</h2>

执行后查看步骤、文件变更与工具调用。如果某步失败，修复边界或输入，而不是立刻换成更大的模型。

```
intent → grants → tools → artifacts
         └─ journal (what ran, what waited, what finished)
```

<h2 id="step-4">4. 仅在需要时接入 OS</h2>

当任务需要跨会话记忆、人工审批、定时唤醒或多 Agent 编排时，再把它提升为 OS 上的耐久流程。Free 从 Work 起步；Builder 起才接入 OS 用量。

<Callout>
如果第一次任务无法向同事复盘“做了什么、改了什么、还缺什么权限”，就还没完成快速开始。
</Callout>
