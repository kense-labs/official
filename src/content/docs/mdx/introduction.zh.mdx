Kense 解决的不是“多一个聊天窗口”，而是把智能体真正放进工作系统：能执行、能恢复、能复用、能被组织约束。产品由两层组成——Kense Work 与 Kense OS——它们共用同一套意图与权限契约。

<h2 id="two-layers">两层，而不是两个产品孤岛</h2>

- Kense Work：local-first 工作入口。模型、文件、工具在本机组合，敏感上下文可以不出境。
- Kense OS：控制面与耐久运行时。编排意图、沉淀记忆、发布策略，并保证中断后可续跑。

<Callout>
先完成一次真实任务，再决定哪些能力需要进入 OS。不要反过来：先上云、再找场景。
</Callout>

<h2 id="for-whom">谁该从这里开始</h2>

如果你要让 Agent 接触真实文件、仓库或内部系统，就不能只依赖一次性对话。Kense 面向需要边界、审计与可恢复执行的团队：平台工程、知识工作、研发交付、受监管环境。
