Work’s first principle: the job runs on the user’s machine. Latency is lower, data is closer, and failure is visible. The cloud is not the default place to execute.

<h2 id="compose">Compose, do not bind one model</h2>

Docs, code, science, and finance experts are replaceable execution profiles. Changing a model should not force you to rebuild grants, file trees, or task definitions.

<h2 id="sandbox">Sandbox and artifacts</h2>

Tools run inside granted sandboxes. Valuable output is files, patches, tables, and records — not chat bubbles. If you cannot diff it, it is hard to put into a team process.

<h2 id="handoff">Hand off to OS</h2>

When a job must wait overnight, for a human, or across teammates, Work hands the same intent to OS. You transfer objects and grants, not a mirror of the whole machine.
